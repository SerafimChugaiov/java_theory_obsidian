### Краткая характеристика метода clone().
Метод **clone()** в Java предназначен для создания копии объекта. Клонированный объект является новым объектом, который содержит те же значения полей, что и исходный объект, но при этом является отдельным экземпляром класса.

Однако не все классы поддерживают метод clone(), поскольку он зависит от реализации интерфейса **Cloneable**. Если класс не реализует интерфейс **Cloneable** и попытаться вызвать метод **clone()**, то будет выброшено исключение **CloneNotSupportedException**.

Кроме этого, следует учитывать, что клонирование объектов может быть глубоким или поверхностным. В случае глубокого клонирования копируются также все ссылки на другие объекты, а при поверхностном клонировании копируются только значения примитивных типов и ссылки на другие объекты сохраняются как ссылки на оригинальные объекты.

Также стоит заметить, что метод **clone()** является защищенным методом, поэтому его можно вызвать только изнутри класса или его наследников.

>[!info]
>**Реализация метода Object.hashCode()** описана как native, т.е. написана НЕ на ЯП Java.
**`native` — это ключевое слово в Java**, указывающее, что метод **реализован не на Java, а на другом языке программирования**, чаще всего — на C или C++. Такой метод подключается к Java через механизм **JNI (Java Native Interface)**.
> **Что это значит на практике:**
>Метод `hashCode()` определён в классе `Object`, от которого наследуются все классы в Java. Когда вы вызываете этот метод у объекта, **выполняется нативный код**, написанный на другом языке. Этот код обычно взаимодействует напрямую с внутренней структурой объекта в памяти и возвращает его уникальный числовой идентификатор (или максимально приближённый к уникальному).
>Пример:
>```java
public native int hashCode();
>```
>Это строка из исходников Java-класса `Object`. Она говорит JVM: _«реализация этого метода находится не в Java-коде, а в сторонней библиотеке, написанной на C/C++»._

### Разница instanceof и getClass
- ` instanceof` проверяет, является ли ссылка на объект с левой стороны экземпляром типа с правой стороны или некоторым его подтипом.

### В чем заключается особенность работы метода clone() с полями объекта типа-ссылки?
Когда вы используете метод `clone()` в Java, он копирует объект. Но если у этого объекта есть поля, которые **ссылаются на другие объекты** (например, массивы, списки, другие классы), то копируются **только ссылки**, а не сами объекты. Это называется **поверхностное клонирование**.

**Глубокое клонирование:**
- Нужно **вручную** клонировать вложенные объекты:

```java
@Override
protected Person clone() throws CloneNotSupportedException {
    Person copy = (Person) super.clone();
    copy.address = address.clone(); // клонируем вложенный объект
    return copy;
}
```

- Вложенные классы (например, `Address`) тоже должны реализовывать `Cloneable` и переопределять `clone()`.****

>[!info]
>**Главное правило:**
> Если в классе есть ссылочные поля — делай **глубокое клонирование**, иначе будет одна и та же ссылка в оригинале и копии.
